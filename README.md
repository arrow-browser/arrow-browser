# Arrow

Arrow is a native macOS re-implementation of [Arc](https://arc.net), the
browser by The Browser Company that is no longer developed. It aims for the
same look and the same features:

- the sidebar with favorites, pinned and "Today" tabs, folders and split views;
- spaces with gradient themes and their own profiles;
- the command bar;
- Little Arrow, Peek, auto-archive, Boosts, notes and easels;
- the same menus and keyboard shortcuts.

- **UI**: SwiftUI, hosted in AppKit windows.
- **Engine**: Chromium, through the C API of the
  [Chromium Embedded Framework](https://github.com/chromiumembedded/cef) (CEF),
  called directly from Swift. No C++ is written.
- **Server**: an optional, self-hostable Go server (`server/`) replaces Arc's
  cloud services (accounts, end-to-end encrypted sync, sharing, AI features,
  update feed, block lists).

## Requirements

- macOS 15 or later on Apple silicon.
- Xcode 26 or later (Swift 6).
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).
- Go 1.27+ only if you run the server.

## Build and run

```sh
make cef        # download and verify CEF (Chromium 156) into Vendor/cef
make            # generate Arrow.xcodeproj and build the Debug app
make run        # build and launch build/DerivedData/Build/Products/Debug/Arrow.app
make test       # unit tests of the model (Packages/ArrowKit)
```

You can also open `Arrow.xcodeproj` (generated by `make project`) and run the
`Arrow` scheme.

URLs passed on the command line open as tabs:
`Arrow.app/Contents/MacOS/Arrow https://example.com`.

### Server (optional)

```sh
cd server && go run ./cmd/arrow-server     # http://localhost:8787
```

Then set the server URL in **Settings ▸ Arrow Cloud**. See
[server/README.md](server/README.md) for the API and the configuration
(`ANTHROPIC_API_KEY` enables the AI features).

### Development notes

- Debug builds pass `--use-mock-keychain` to Chromium: they are ad-hoc signed
  with a new signature at each build, which would otherwise make the Keychain
  prompt for "Arrow Safe Storage" every time. Release builds use the Keychain.
- In Debug builds Arrow also never shows Keychain prompts: saved passwords
  and cards written by an earlier build (another signature) just don't load.
- Debug builds can be driven from a script, which is handy to check the UI
  without clicking:
  `swift scripts/arrowctl.swift open https://example.com` (see
  `Sources/Arrow/App/DebugAutomation.swift` for the actions).
  This remote control is not compiled into release builds.
- `swift scripts/make-icon.swift` regenerates the app icon.
- `swift scripts/make-sounds.swift` regenerates the sound effects
  (`Resources/Sounds`).

### Publishing an update

Arrow installs updates only when the archive is signed with the Ed25519 key
whose public half is in `SUPublicEDKey` (`Resources/Arrow-Info.plist`), as
Sparkle does.

1. Once: `swift scripts/sign-update.swift generate-keys`. Like Sparkle's
   `generate_keys`, it keeps the private key in the login Keychain ("Arrow
   Update Signing Key") and prints the public key for `SUPublicEDKey`. Back the
   private key up: installed copies only accept updates signed with it.
2. Zip the app: `ditto -c -k --keepParent Arrow.app Arrow-<version>.zip`.
3. `swift scripts/sign-update.swift sign Arrow-<version>.zip` prints the
   `edSignature` and `length` (in CI, pass the key in `ARROW_UPDATE_PRIVATE_KEY`).
4. Add the release to the server's `releases/releases.json` (see
   [server/README.md](server/README.md)).

## Repository layout

| Path | Contents |
|---|---|
| `Sources/CEF` | Clang module exposing CEF's C headers to Swift |
| `Sources/Arrow/CEF` | Swift layer over the CEF C API: runtime, browsers, handlers, ref counting |
| `Sources/Arrow/Model` | App state: `BrowserStore`, `WebTab`, `WindowState`, command bar |
| `Sources/Arrow/Views` | SwiftUI views: sidebar, content, command bar, library, settings… |
| `Sources/Arrow/Services` | Downloads, favicons, extensions, import, updates, Arrow Cloud client |
| `Sources/ArrowHelper` | Chromium sub-process entry point (renderer, GPU…) |
| `Packages/ArrowKit` | Engine-independent model: spaces, tabs, themes, URL parsing, history, boosts |
| `server/` | Go server replacing Arc's cloud services |
| `docs/` | [Architecture](docs/ARCHITECTURE.md), [feature parity](docs/FEATURES.md), [Arc services](docs/ARC_SERVICES.md) |

## Data

Arrow stores its data in `~/Library/Application Support/Arrow`:

- `State/`: sidebar, settings, history, boosts and notes as JSON, with
  rotating backups.
- `Default/` and `Profiles/<id>/`: one Chromium profile per Arrow profile.
- `Extensions/`: installed Chrome extensions.

**Import from Arc** (Arrow menu ▸ Import from Another Browser…) brings over
Arc's spaces, their themes, pinned tabs, folders and favorites.
